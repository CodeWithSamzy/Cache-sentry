# Chrome Web Store submission notes

Copy/paste material for the store listing form. Keep it in step with the code:
the permission list here must match `manifest.json` exactly.

## Single purpose

Cache Sentry passively detects potential web cache deception: a request that
carries a session cookie and receives a cacheable response for a URL that looks
like a static asset. It reports the signal to the user in the toolbar popup.

## Permission justifications

**`webRequest`** -- the entire check reads request headers (is a session cookie
being sent?) and response headers (`Content-Type`, `Cache-Control`, `Age`,
`X-Cache`, `CF-Cache-Status`, `Vary`). Without it there is nothing to analyse.

**`webNavigation`** -- findings are per tab, and the extension resets a tab's
findings when that tab navigates. It reads the frame id and URL of top-level
navigations only; it does not read page content.

**`storage`** -- MV3 service workers are stopped when idle. Findings are written
to `chrome.storage.session` so the badge count and the popup survive that
restart. Session storage is cleared by Chrome when the browser closes.

**Host permission `<all_urls>`** -- web cache deception is a server-side
misconfiguration, not a property of a particular site, so any site the user
visits can be affected. A shorter host list would silently miss the cases the
extension exists to catch. The extension does not modify requests or responses;
it only observes headers (`webRequest` is used without blocking).

## Remote code

None. All logic ships inside the package; there is no `eval` of remote content,
no bundled third-party library loaded at runtime, and no server component.

## Data usage disclosures

- Does not collect or transmit any user data.
- Does not sell or transfer data to third parties.
- Does not use or transfer data for purposes unrelated to the single purpose.
- Does not use or transfer data to determine creditworthiness or for lending.

Findings are stored on the user's device only, in session storage, and are
cleared when the browser closes.

## Privacy policy URL

Publish `PRIVACY.md` (for example as a GitHub Pages page or a gist) and paste
that URL into the listing. The store requires a reachable URL, not a document
in the repository.

## Assets

Icons are in `icons/` and are generated by `node tools/make-icons.js`. The store
also wants a 128x128 icon (present) plus at least one screenshot of the popup,
which has to be captured from a real Chrome window.
